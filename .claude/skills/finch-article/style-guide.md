# 과학드림 스타일 가이드 (Finch 기사용)

이 파일은 기사 작성 에이전트가 **반드시** 읽고 따르는 고정 레퍼런스다.
원문 텍스트 샘플은 `ref/015.txt`, `ref/012.txt`, `ref/030.txt`에 있다.

---

## 1. 핵심 목표 (3가지)

1. **쉽게** — 전문 용어를 쓸 때는 반드시 한 문장 안에 쉬운 풀이를 끼워 넣는다.
2. **재미있게** — 의문 → 가설 → 증거 → 반전의 리듬을 만든다.
3. **기승전결** — 한 편의 이야기처럼 읽히게 한다. 나열식 서술 금지.

## 2. 글의 뼈대 (6~10문단 기준)

| 역할 | 분량 | 핵심 |
|---|---|---|
| 훅 | 1문단 | 구체적 숫자·장면·의외의 사실로 시작 ("약 450km 떨어진 곳에 작은 모래섬 하나가 있습니다") |
| 의문 제기 | 0.5~1문단 | 독자가 궁금해야 할 질문을 명시 |
| 배경 | 2~3문단 | 기본 정보, 왜 이게 특이한가 |
| 연구 등장 | 1~2문단 | 과학자 이름·소속·연구 연도 등장 |
| 증거 제시 | 2~3문단 | 논문의 핵심 발견, 수치 |
| 반전/핵심 | 1~2문단 | 결정적 뒤집기 또는 의외의 사실 (억지로 만들지 말 것) |
| 여운 | 1문단 | 독자에게 남는 질문·의미 |

**반전이 억지스러우면 넣지 않는다.** 이야기 자체의 흥미가 살면 충분하다.

## 3. 문장 말투 (설명체)

**사용하는 종결어:**
- `~합니다` — 기본 (남용 금지, 한 문단에 2번 이하)
- `~하죠` — 강조·공감 유도
- `~인데요` — 전환·연결 (문단 사이)
- `~거죠`, `~거예요` — 결론 제시
- `~았/었/였습니다` — 과거 사건 서술
- `~있습니다`, `~없습니다` — 사실 확인

**한 문단에 종결어 최소 2종 이상 섞기.** `~합니다`만 반복하면 죽은 글이 된다.

**독자 호응 유도 문장 (적절히):**
- "참 신기하지 않나요?"
- "있었을까요? — 있었습니다!"
- "도대체 왜 이런 일이 벌어진 걸까요?"
- "그런데 여기서 의문이 하나 생깁니다."

## 4. 금지 사항 (사용자 명시)

- ❌ "자~" 같은 유튜브 전용 추임새를 **의식적으로** 넣지 말 것
- ❌ "그런데!" 단독 문단 금지 (자연스러운 전환이면 OK)
- ❌ "과학은 세상을 보는 창! 지금까지 과학드림이었습니다" 식의 엔딩 시그니처 절대 금지
- ❌ 원문 영어 기사의 문장을 직역 금지 (표절 위험). 사실만 뽑아 한국어로 재구성
- ❌ **한국어 본문에 em-dash(`—`) 또는 en-dash(`–`) 사용 금지.** " — "는 영문 번역체 느낌이 강해 어색하다. 대안:
  - 부연 설명: 쉼표(`,`) 또는 마침표로 끊기 (`. `)
  - 제목 부제 분리: 콤마 또는 띄어쓰기 (예: "큰 제목 부제" 또는 "큰 제목, 부제")
  - 삽입구: 괄호 사용 (`(...)`)
  - "출처:" 앞: 마침표+공백 (`. 출처:`) 또는 괄호 (`(출처: ...)`)
- ❌ **단어 주변에 작은따옴표(`'...'`) 남용 금지.** 특히 아래 경우는 따옴표를 쓰지 말 것:
  - 한글 전문용어 + 영문/한자 병기: `'스타톨리스(statolith)'` → `스타톨리스(statolith)`
  - 단순 명사: `'빗소리'`, `'대조군'`, `'반대 방향'` → 그냥 `빗소리`, `대조군`, `반대 방향`
  - 따옴표를 써도 되는 경우: 의인화된 동사(`'듣고'`, `'보는'`), 은유적 별명(`'우주의 바다레몬'`), 실제 누군가의 인용구

## 5. 고유명사·수치 규칙

**인명 (과학자):** 한글 + 영문 + 소속 + 직책
- 좋음: "일본 소켄다이 국립대학원의 타카히로 요네자와(Takahiro Yonezawa) 박사는"
- 나쁨: "Yonezawa 박사는"

**학명/종명:** 한글 + 영문 병기
- 좋음: "큰바다사자(Steller sea lion)", "티타노보아(T. cerrejonensis)"

**수치:** 구체적으로, 단위 생략 금지
- 좋음: "약 1,400km", "시속 280km", "1761년 7월 31일"
- 나쁨: "약 1400km", "시속 280", "1760년대"

**연구 인용:** 연도 + 저널/논문 유형 명시
- 좋음: "그는 2014년 논문에서", "2009년 《네이처》에 발표된 연구에 따르면"
- 나쁨: "연구에 따르면" (출처 불명)

## 6. 문단 호흡

- 한 문단 **3~5문장**, 길어도 6문장 이하
- 한 문장 **최대 50자 내외** 권장 (가독성)
- 쉼표로 3번 이상 끊어지면 문장 분할
- 문단 간 **개행 1줄** (HTML에서는 `<p>` 분리)

## 7. 표절 회피 (중요)

원문 영어 기사를 한 문단씩 번역하는 식은 **절대 금지**. 다음을 따른다:

1. 원문에서 **사실만** 추출 (수치·연도·고유명사·인과관계)
2. 추출한 사실을 기반으로 **한국어 이야기로 재구성** (문장 구조 완전히 재작성)
3. 핵심 팩트는 **학술 논문 1개 이상으로 교차 검증** (Google Scholar, arXiv)
4. 원문 기사의 이미지·인용구 직접 사용 금지

**자가 검증 질문:**
- 이 문장을 원문과 나란히 놓았을 때, 같은 순서의 같은 정보 나열인가? → 재작성
- 원문에만 있는 표현을 그대로 썼는가? → 재작성

## 8. 참고문헌 섹션 (본문 맨 끝)

```html
<h3>참고문헌</h3>
<p class="ql-size-small">
1. Yonezawa, T., et al. (2009). "Molecular phylogenetic study on the origin and evolution of Mustelidae." <em>Gene</em>, 396(1), 1-12. DOI: 10.1016/j.gene.2006.12.040<br>
2. Guérout, M., & Romon, T. (2015). <em>Tromelin: L'île des esclaves oubliés.</em> CNRS Éditions.<br>
</p>
```

- **언론 원문 링크(New Scientist / Scientific American / The Atlantic) 금지**
- 학술 논문 DOI·저자·연도·저널명만
- 2~4개가 적당

## 9. 이미지·캡션

**본문 이미지 (2~3장):**
```html
<p class="ql-align-center">
  <img src="이미지_URL" alt="대체 텍스트">
</p>
<p class="ql-align-center"><em>캡션 텍스트 — 출처: Wikimedia Commons (CC BY-SA 4.0) / 저자명</em></p>
```

**썸네일:** 폼의 `thumbnail` 필드에 URL만 입력 (본문에는 넣지 않음 — ArticlePage가 자동 삽입)

**캡션 내용:**
- 이미지가 무엇을 보여주는지 (1~2문장)
- **반드시 출처 + 라이선스 + 저자** 표기
- 이탤릭(`<em>`)으로 감싸면 CSS가 자동으로 회색·작은 글씨로 렌더링

**허용 이미지 소스:**
- Wikimedia Commons (CC BY / CC BY-SA / Public Domain)
- NASA / ESA / JWST / Hubble (Public Domain / 공식 배포)
- Unsplash (무료 상용 이용)
- **원문 사이트 이미지 절대 금지**

## 10. 체크리스트 (작성 후 자가 검증)

- [ ] 훅이 구체적 숫자·장면으로 시작하는가?
- [ ] 독자 질문을 최소 2회 던졌는가?
- [ ] 과학자 이름이 한글+영문+소속으로 나오는가?
- [ ] 종결어가 2종 이상 섞였는가?
- [ ] 한 문단이 6문장을 넘지 않는가?
- [ ] 원문 문장을 직역한 부분이 없는가?
- [ ] 참고문헌에 학술 논문 2개 이상 있는가?
- [ ] 이미지 캡션에 출처+라이선스가 있는가?
- [ ] 엔딩이 "과학드림이었습니다" 같은 시그니처로 끝나지 않는가?
